# Starter pack authoring route

**Start with the baseline.** This is the internal framework-contributor route. Shared-vault paths resolve from your accessible vault root, not this repository. Source IDs below resolve through the [baseline register](baseline.md#governing-source-register).

1. Read the [baseline](baseline.md): purpose, candidate/source identity, boundaries, decisions and readiness. Check **V0**, “Current interpretation,” before applying historical sources.
2. Find the relevant unit in the [team map](team-map.md) and participation/gap entries in the [single coverage record](role-coverage.md). Read **V1**, accepted hierarchy and the selected team charter; follow only the detailed sources cited for the selected Role/Profile.
3. Use the [shared Role/Profile format](definition-format.md). Resolve required inputs and shared-policy references before drafting. A missing governing decision stays a blocker; an assigned downstream definition gap keeps its owner and next action.
4. Select the [governance-change fixture](fixtures/governance-change.md) or [tooling-change fixture](fixtures/tooling-change.md). Read the targeted sections below, then the fixture's own cited inputs. Preserve expected outcomes as paper expectations.

The [worked Agent Governance Officer example](examples/roles/agent-governance-officer.md) illustrates the format. It is documentation, not a runtime Role resource. Future runtime Roles belong under `src/agent_company/resources/roles/` in the packaged build; this guide does not supply or activate them.

The register supplies exact identities, vault-relative locators and retained-version retrieval. The frozen authoring packet must explicitly identify permitted governing sources and sections; a register entry alone does not authorize reading it. Exclude research/author reasoning and conversations from the packet.

Neither paper fixture supplies approved parent plans, human decisions or a Wave Admission Record. Product Planning/Human Leadership must supply those before actual authorization/admission. This gap does not block bounded authoring. Trace expected actors, artifacts, decisions, handoffs and stop conditions through planning, delivery, recorded outcome and retrospective input. Missing, stale or conflicting required inputs block the affected conclusion. Report that gap; do not invent authority or actual approvals. The baseline owns these [paper-evidence limits](baseline.md#selected-paper-fixtures-and-exclusions).

The fresh author receives the frozen product guidance, scoped assignment and permitted governing sources, then creates the one example. A separate reviewer checks required fields, exact source versions, authority/write boundaries, completion evidence and handoffs. Record missing guidance and repair it before repeating an affected trial. This checks framework authoring usability; it does not establish runtime isolation or company-only onboarding. See the baseline’s authoring and publication rules.

For issue working data, use the [task-workspace contract](task-workspace.md). Documentation usability checks do not establish workspace enforcement or runtime acceptance.

**Company-specific authors:** Use accessible framework guidance and your company's governing sources with the reusable format. This internal vault route is not your prerequisite. Complete company onboarding/distribution and its acceptance are not supplied by this pack. [Recorded audience decision](baseline.md#confirmed-authoring-and-publication-decisions).
