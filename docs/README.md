# Starter pack authoring route

**Start with the public baseline.** These repository documents supply the shared rules for Role/Profile authoring. A Company-specific assignment adds its own accessible governing inputs.

1. Read the [baseline](baseline.md): purpose, authority, source integrity, independence, outcomes and publication rules.
2. Find the unit in the [team map](team-map.md) and its participation/gaps in the [coverage record](role-coverage.md).
3. Use the [shared Role/Profile format](definition-format.md). Resolve required inputs and policy references before drafting. A missing governing decision blocks its dependent action; an unfinished definition retains its owner and next action.
4. Select the [governance-change fixture](fixtures/governance-change.md) or [tooling-change fixture](fixtures/tooling-change.md). Use its public rule links and scenario inputs; preserve expected outcomes as paper expectations.

The [worked Agent Governance Officer example](examples/roles/agent-governance-officer.md) illustrates the format. It is documentation, not a runtime Role resource. Future runtime Roles belong under `src/agent_company/resources/roles/` in the packaged build; this guide does not supply or activate them.

A frozen authoring packet identifies permitted documents, sections and revisions. Exclude research, author reasoning and conversations. Neither fixture supplies approved parent plans, human decisions or a Wave Admission Record. Product Planning/Human Leadership must supply those before actual authorization/admission. Their absence does not block bounded authoring; see [paper-evidence limits](baseline.md#selected-paper-fixtures-and-exclusions).

For a usability check, give a fresh author the frozen guidance, scoped assignment and permitted governing inputs, without the worked answer. A separate reviewer checks fields, versions, authority/write boundaries, completion evidence and handoffs. Record missing guidance, repair it and repeat affected checks. This tests authoring usability, not runtime isolation or complete Company onboarding. See [authoring and publication rules](baseline.md#authoring-and-publication-rules).

For issue working data, use the [task-workspace contract](task-workspace.md). Its implementation and acceptance limits are separate from paper authoring checks.
