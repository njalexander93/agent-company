# Inspect a worked definition

## Inputs

- Working: the exact candidate and assigned review scope. [agent-governance-officer.md](agent-governance-officer.md) is the worked example.
- Reference: [field guidance](../authoring/definition-format.md#role-field-guidance), [review criteria](../authoring/definition-format.md#review-and-maintenance), the selected Role entry in [coverage](../framework/role-coverage.md#03-agent-governance-officer), and the candidate's [public rule links](agent-governance-officer.md#governing-sources-and-open-gaps).
- For each review question read the affected candidate fields and their corresponding public rule sections. Read [independent context rules](../framework/baseline.md#context-and-independent-assurance) before assembling reviewer inputs.

## Process

1. Follow the assigned fields and rule links; keep the worked answer out of fresh-author packets.
2. Compare duties, owner/write boundaries, context, outcomes and gaps with the applicable rules. Repeat for all fields in the assigned review scope; a partial pass does not imply whole-definition coverage.
3. Return findings or assigned example edits with exact identity and scope. Preserve the worked-documentation status.

## Outputs

Scoped findings in the assigned review record, or an authorized example diff. No runtime Role or installed Skill is produced.

## Human check

Use the existing [PR check](../CONTEXT.md#human-check) to verify scope and exact review disposition, without treating examples as activation.
